## @Elyor2011 — frontend-queue

Самое приоритетное сейчас — по этой части ещё вообще ничего не запушено, а
это ключевой момент демо (QR/booking-код сканируют/показывают судьям).

1. Список салонов: `GET /api/salons` — карточки с адресом. Карта на карте не
   обязательна, если не успеваешь — просто список карточек с координатами
   текстом.
2. Выбрал салон → мастера этого салона, **только те, кто на линии**:
   `GET /api/masters?salonId=<id>&onDuty=true`.
3. Выбрал мастера → выбрал услугу (`GET /api/services`) → две кнопки:
   "Сейчас" (обычный `POST /api/queue`) или "На время" (то же самое +
   `scheduledFor` в теле, ISO-строка будущего времени).
4. После записи покажи клиенту его booking ID (это `_id` созданной записи)
   крупно на экране — этого достаточно вместо настоящего QR-сканирования,
   просто подпиши "покажите этот номер ресепшну".
5. Статус оплаты клиенту виден через тот же `GET /api/queue/:masterId` — если
   у его записи `paid: true`, покажи "✅ Оплачено".

Если время совсем поджимает — пункты 1–3 обязательны для демо, 4–5 можно
урезать до одной строки текста.
